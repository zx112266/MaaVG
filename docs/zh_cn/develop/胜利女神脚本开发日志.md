## 1. 界面约定：两个「公告」不是一回事

| 对比项 | 公告弹窗（推送） | 公告入口（按钮） |
|---|---|---|
| 长什么样 | 画面居中大面板，盖住标题页 / 大厅 | 标题页左侧竖列第 1 个，铃铛 + 「公告」 |
| 文字锚点 | 「活动公告」「系统公告」页签 | 只有「公告」两个字，无页签 |
| 处理方式 | 关掉 | **只识别，绝不点击** |

**硬规则：公告入口只识别不点击。** 任何脚本都不允许对 `x∈[0,140] ∧ y∈[180,420]` 区域发点击（那里还有 16+ 适龄提示、客户中心，误触有风险）。

### 1.1 两个「公告弹窗」要分清

| 对比项 | ① 标题页预告弹窗 | ② 进大厅后的活动公告列表 |
|---|---|---|
| 出现时机 | 冷启动到标题页时 | 点「点击开始」进大厅后自动弹 |
| 外观 | 文档式长文（亲爱的指挥官 / 更新内容 1. 2. …） | 白底卡片列表 + 4 张活动图 |
| 页签 | 无 | 「活动公告」/「系统公告」，系统公告带红点 |
| 底部勾选 | 有「一周内不再显示」≈(82,1095) | 没有 |
| 关闭 × | ≈(640, 420) | ≈(655, 276) |
| 弹窗下沿 | y≈1120 | y≈1292（底栏 y≈1500 仍露出） |

处理顺序（标题页）：勾「一周内不再显示」→ 点 × → 等「点击开始」。

## 3. 大厅判据（每个操作后「回到大厅」的依据）

### 3.1 稳定特征

| 锚点 | ROI | score | 弹窗遮挡 |

| 作战出击 | [500,1230,200,90] | 0.99995 | 会 |
| 方舟 | [520,1090,170,110] | 0.9558–0.99994 | 会 |

| 底栏五页签 | [60,1480,620,60] | 0.997–0.9999 | **不会** |

### 3.2 为什么用「三锚点串联」

**底栏不是大厅独有的**——妮姬 / 部队 / 物品栏 / 队员招募 页面底部都有同样的五页签。只有 `作战出击 + 方舟 + 前哨基地` 三个方块同时出现才是大厅首页。

### 3.3 不能当判据的特征（会变）

`185K+`、`59670 K`（资源数）、`LV.334`（等级）、`通关【23-11】`（进度）、各种横幅（前线犒赏 / FIRST LYCORIS PASS / 真彩 Flavor 轮换）、指挥官对话气泡（随机文案）。

## 4. 脚本结构

### 4.1 `nikke_launch.json` —— 启动脚本（11 节点）

```
启动妮姬 (StartApp，35s 窗口)
 ├─ 公告弹窗（标题页预告，命中页签 → ClickKey 4 返回关闭）→ 等待点击开始
 ├─ 等待点击开始（OCR 命中 → 点击）→ 三路判定
 │    ├─ 活动公告弹窗_关闭 → 点 (655,276) → 大厅_底栏确认
 │    ├─ 大厅_底栏确认（物品栏/队员招募）→ 结束
 │    └─ 大厅_作战出击确认 → 结束
 └─ 35s 无命中 → 停滞重启_1 → 停滞_重新拉起_1 → 停滞重启_2 → 停滞_重新拉起_2 → 停滞放弃
```

### 4.2 `nikke_common.json` —— 公共判据（7 节点）

```
回到大厅_确认  ← 以后所有脚本都接这个
 ├─ 活动公告弹窗_关闭_通用（命中页签 → 点 (655,276)，3s 超时）
 ├─ 大厅_确认 → 判据_作战出击 → 判据_方舟 → 判据_前哨基地 → 结束
 └─ 15s 都走不通 → 大厅_未确认（StopTask，留下明确节点名便于排查）
```

用法：任何操作节点写 `"next": ["回到大厅_确认"]`。

### 4.3 `nikke_free_gift.json` —— 付费商店免费礼包（12 节点）

```
付费商店(157,1077) → 等待商店加载 → 选礼包页签(155,360)
  → 普通礼包 → 每日页签(297,447) → {已售罄 跳过 | 可领取 → 领取(360,962)}
  → 每周页签(487,447) → {同上} → 返回大厅 → 回到大厅_确认
```

关键：图标栏中心 y≈360，x = 58/155/250/348/442/535；每日与每周的免费礼包坐标完全相同可复用；红点 = 可领取（领完自动消失）。

### 4.4 `nikke_shop.json` —— 普通商店免费商品 + 免费刷新（9 节点）

```
商店_入口(168,1152)
 ├ 商店_买免费商品：OCR「100% SALE」roi[130,908,180,40] → 点 (217,927)
 │    ├ 命中 → 购买弹窗_确认：OCR「购买道具」→ 点 (492,1222)
 │    │          → 奖励_领取：OCR「点击领取奖励」→ 点 (360,962)
 │    │          → 商店_免费刷新检测：ColorMatch「免费」角标 → 点 ⟳(396,670)
 │    │                ├ 命中 → 通知弹窗_确认：OCR「是否更新商品」→ 点 (528,942)
 │    │                │          → 回到「商店_买免费商品」再买一轮
 │    │                └ 无角标 → 商店_结束
 │    └ 8s 无命中 → 商店_结束
 └ 商店_结束 → 商店_返回大厅（OCR「返回」→ 点 (78,1480)）→ 大厅_确认（作战出击）
```

**语义**：能白嫖就白嫖（买 → 领 → 免费刷新 → 再买 → 再领），没有可买的或没有刷新机会时**自动退回大厅**，不停在商店页。

## 5. 停滞重启设计（2026-11-13 定稿）

| 结论 | 依据 |
|---|---|
| 停滞窗口 **35 秒** | 实测冷启动：15 s 仍 `[2/2] 消息同步`，**23 s** 才出现「点击开始」；取 20 s 会误判正常启动为卡死 |
| 用 `on_error` 而非 `max_hit` | `max_hit` 只让节点失效、流程空转；`on_error` 才真正接上重启节点 |
| **最多重启 2 次** | `重启_1 → 拉起_1 → 重启_2 → 拉起_2 → 停滞放弃` |
| 重启动作 | `StopApp` + 3 s + `StartApp` |
| 更新分支已删除 | 旧 `检测到更新_已停止` 把「开始检查更新程序集」当更新信号，而**每次正常冷启动都会显示这行**，稳定误停 |

`on_error` 语义用 4 秒短超时探针实测通过：节点序列与预期完全一致。

## 6. 踩过的坑（技术）

| # | 坑 | 结论 |
|---|---|---|
| 1 | Pipeline JSON 写 `//` 注释 | 不支持，必须纯 JSON |
| 2 | `run_pipeline` 不传 `resource_path` | MaaMCP 用空资源目录（没 OCR 模型），调用挂到超时且不报错。**必须传 `G:\MaaVG\assets\resource`** |
| 3 | ROI 裁掉文字半个字 | 如 `[430,1200,220,120]` 把「作战出击」的「击」裁掉 → failed；要完整包住文字 |
| 4 | 节点 `timeout` 的语义 | 父节点 timeout 决定 **next 列表整体轮询预算**（默认 20 s），子节点写 timeout 无效；预算要写在发起方节点上 |
| 5 | 全屏 OCR 识别「点击开始」只有 0.94 | 整屏 20+ 候选竞争 + 文字呼吸动画；**必须带 ROI**（ROI 下 20/20 次 100% 命中，score ≥0.989） |
| 6 | `stop_pipeline` 后 controller 立即失效 | 必须重新 `connect_adb_device` |
| 7 | MaaMCP 单次 `run_pipeline` 约 60 s 客户端上限 | 超时后任务仍在后台跑，客户端报 Request timed out |
| 8 | 无线调试开了但扫不到设备 | `adb mdns check` 触发重新广播后才出现；端口每次开无线调试都会变 |
| 9 | `ocr(region=...)` 偶发 `'NoneType' object has no attribute 'all_results'` | MaaMCP 工具缺陷，不影响 Pipeline 内部 ROI 识别 |
| 10 | 探针/临时 pipeline 文件删不掉 | 被 MaaMCP 占句柄，需 `stop_pipeline` 后再删 |
| 11 | 游戏冷启动偶发卡资源校验（67% / 22%） | 游戏自身行为，等待或强杀重开；不是脚本问题 |
| 12 | `ColorMatch` 的 `lower`/`upper` 写成**一维数组** | 直接让 MaaFramework 原生层崩溃（`Connection closed` → `Not connected`）。正确写法是**二维**：`"lower": [[200,70,30]]`、`"upper": [[255,160,120]]`，`method: 4` = RGB |
| 13 | 弹窗按钮点不到（弹窗被“点外部”关掉） | **肉眼估计的按钮位置偏低 ~250 px**。必须先用 `ocr()` 拿文字 box（`确认` [501,927]、`购买` [464,1206]），用 box 中心当点击点 |
| 14 | 购买按钮只有下沿能吃点击 | 视觉范围 y1158–1232，实际可点区 **y ≥ 1198**；点视觉中心会落进死区 |
| 15 | 时间条宽度随文字变化 | `1小时20分钟` → `剩余59分钟52秒` 时整条右移 ~25 px，**角标与 ⟳ 跟着漂**；固定 ROI/点击点会失准，应改“横条 ROI + `target_offset`” |
| 16 | 任一 pipeline 文件解析失败 → 整个 resource 加载失败 | 日志 `key already exists [key=_入口]`；表现却是 `run_pipeline` 报「获取 Tasker 失败，请确保 controller_id 有效」。**resource 只在 MaaMCP 启动时加载一次**，修完要重启插件 |
